# Beryl v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Beryl compiler that type-checks and ownership-checks real Beryl source, then emits either a native executable (via C + clang) or EnforceScript for Arma Reforger.

**Architecture:** Single-pass-per-stage C11 compiler, arena-allocated throughout, zero dependencies. Source → tokens → AST → resolved/typed AST → monomorphized AST → ownership-checked → backend. Both backends emit from the **typed AST**, sharing a lowering-helpers module.

**Tech Stack:** C11, clang 22 (LLVM-MinGW), no build system beyond a shell script. No third-party libraries — not one.

**Spec:** `docs/superpowers/specs/2026-09-03-beryl-language-design.md`

## Design correction discovered during planning

The spec (§7) specifies a shared low-level **MIR** feeding both backends. That is wrong for
this language pair, and the plan deliberately deviates:

**EnforceScript is a high-level language.** Lowering to a low-level SSA IR and then
reconstructing classes, methods, `foreach` loops and expressions from it would destroy exactly
the structure the Enfusion backend needs to emit, and would make the generated script
unreadable — which matters, because the user has to debug it inside Workbench.

**Both backends therefore emit from the typed, monomorphized AST**, sharing `src/ir/lower.c`
for drop insertion, temporary management, and desugaring (`try`/`orelse`/compound assignment).
This is less code, produces better EnforceScript, and loses nothing on the native side because
clang performs all real optimization. A true MIR becomes worthwhile only alongside a direct
machine-code backend, which is v2.

**Action:** spec §7 and §9.1 updated to match; `src/ir/mir.c` is not built in v0.1.

## Global Constraints

- **C11**, compiled with clang. No dependencies, no build system, no generated code.
- **Arena allocation only.** No `malloc`/`free` outside `arena.c` and the CLI's file I/O.
- **Compiler binary < 1 MB**, zero DLL dependencies beyond the CRT.
- **Every diagnostic has a stable `BE####` code** and an entry in `docs/DIAGNOSTICS.md`.
- **Enfusion output: UTF-8 with no BOM, tab-indented, one class per file, prefixed names.**
- **No feature ships without a test.** TDD: failing test first, always.
- **Commit after every task.**
- Error code ranges: `BE01xx` lexer · `BE02xx` parser · `BE03xx` resolve/type · `BE04xx`
  ownership · `BE05xx` const-eval · `BE06xx` security · `BE07xx` enfusion profile ·
  `BE08xx` driver/manifest.

**Newline rule (normative).** The lexer emits `TK_NEWLINE` at a line break only when **all**
hold: (a) bracket depth for `(` and `[` is zero; (b) the previous significant token can end an
expression — literal, identifier, `self`, `)`, `]`, `}`, `?`, `break`, `continue`, `return`;
(c) the next significant token is not a continuation — not a binary operator, `.`, `)`, `}`,
`]`, `,`, `{`, `catch`, `orelse`, `as`. Consecutive newlines collapse to one.

**Diagnostics:** `BE0101` unterminated string · `BE0102` unterminated char · `BE0103` invalid
escape · `BE0104` invalid numeric literal · `BE0105` unexpected character · `BE0106` integer
literal too large · `BE0107` block comments unsupported (with help: use `//`).

**Test cases:** every keyword lexes to its kind, and `letter` lexes as `TK_IDENT` not `TK_LET`
(prefix trap). Operators including maximal-munch pairs `== != <= >= && || << >> += -= *= /=
%= -> => ..`. Integers in dec/hex/binary/octal with `_` separators; suffix capture. Floats
`1.5`, `1e-9`, `1.5f32`; `1..2` lexes as INT DOTDOT INT, **not** as a float. Strings with all
escapes; unterminated string reports `BE0101` at the opening quote. `//` comment skipped;
`//!` becomes `TK_DOC`. Newline rule: `a\n+b` (leading operator on next line) emits no
newline; `return x\n+ y` continues per (c); `f(\n1,\n2)` emits none; `let a = 1\nlet b = 2`
emits exactly one. Golden: full token dump of a representative file.

Expression parsing is Pratt. Binding powers, loosest first: `orelse`/`catch` · `||` · `&&` ·
comparison (non-associative) · `|` · `^` · `&` · `<<` `>>` · `+` `-` · `*` `/` `%` · unary

**Diagnostics:** `BE0201` expected token · `BE0202` expected expression · `BE0203` expected

`BE0206` `self` only permitted as first parameter of a method · `BE0207` default value on
`inout`/`sink`/`set` parameter · `BE0208` non-associative comparison chain (`a < b < c`) ·
`BE0209` missing `module` declaration.

0; at item level, skip to the next `fn`/`struct`/`enum`/`const`/`test`/`pub`. This is what
lets one file report several genuine errors instead of one plus noise.

**Test cases:** precedence — `a + b * c` groups as `a + (b * c)`; `a * b + c` as `(a*b)+c`;
`!a && b` as `(!a) && b`; `a as i64 + 1` as `(a as i64) + 1`; right-assoc none in v0.1.

Recovery: a file with two independent syntax errors reports both.

## Task 6: Const evaluation and generics

**Files:** Create `src/sema/constfold.{c,h}`, `src/sema/monomorph.{c,h}`,
`tests/unit/test_const.c`, golden pairs

**Produces:**

```c
typedef struct { bool ok; Type *type; union { int64_t i; double f; bool b; Str s; }; } ConstVal;
ConstVal const_eval(Arena *a, DiagBag *d, Program *p, Expr *e);
bool     monomorphize(Arena *a, DiagBag *d, Program *p);   /* rewrites p in place */
```

The evaluator is a **sandbox by construction**: it interprets only pure expressions over
integers, floats, bools and strings. It has no file, network, environment or clock access —
there is nothing to disable, because none of it is implemented. Bounded at 100 000 steps and
1 MB to make non-termination a diagnostic rather than a hang.

Monomorphization walks call sites, instantiates each `(generic item, type args)` pair once
into a mangled clone, and memoizes. Recursion depth is capped at 64 instantiations deep.

**Diagnostics:** `BE0501` not a constant expression · `BE0502` division by zero in constant ·
`BE0503` constant overflow · `BE0504` step/memory limit exceeded · `BE0505` array length must
be a non-negative constant · `BE0506` generic recursion limit exceeded · `BE0507` unsatisfied
trait bound.

**Test cases:** `[i32; 2 + 3]` yields length 5; `[i32; -1]` → `BE0505`; `1/0` → `BE0502`;
`i32` constant overflow → `BE0503`; a const-fn recursing forever → `BE0504`. Monomorphization:
`max<i32>` and `max<f32>` produce two distinct functions with mangled names; calling
`max<i32>` twice produces exactly one instance; a generic struct `Pair<T>` instantiates its
fields; an unsatisfied bound reports `BE0507`.

## Task 7: Ownership checker

**Files:** Create `src/sema/ownership.{c,h}`, `tests/unit/test_ownership.c`, golden pairs

**Produces:**

```c
bool ownership_check(Arena *a, DiagBag *d, Program *p);
```

Because Beryl has structured control flow only (no `goto`), this is a structural AST walk
rather than a CFG fixpoint: sequence composes states, `if` merges both branches
conservatively, loops iterate to a fixpoint (bounded at 8 passes, which is ample for
structured code).

Per-binding lattice: `UNINIT → INIT → MOVED`, plus an active-borrow set recording
`(root binding, field path, kind)` where kind is shared or exclusive.

**Rules enforced:** reading `UNINIT` or `MOVED` is an error · assigning to a `let` binding
after initialization is an error · two overlapping exclusive borrows in one call is an error ·
a shared borrow overlapping an exclusive one is an error · a `set` parameter must be `INIT` on
every path that returns · a `sink` argument must be `INIT` and becomes `MOVED`.

**Diagnostics:** `BE0401` overlapping exclusive borrows · `BE0402` assignment to immutable
binding · `BE0403` use after move · `BE0404` `set` parameter not initialized on all paths ·
`BE0405` use of possibly-uninitialized binding · `BE0406` cannot move out of a borrow ·
`BE0407` cannot mutate through a `let` borrow.

`BE0401` must render with **both** spans labelled, per the spec's §9.3 example.

**Test cases:** each diagnostic gets a golden pair. Positive: moving into a `sink` then
rebinding is fine; `if c { consume(sink x) } else { consume(sink x) }` is fine (both branches
