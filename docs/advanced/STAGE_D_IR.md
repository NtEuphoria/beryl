## Objective and dependency gates

Introduce a representation that makes evaluation order, storage access, checked
operations, control flow and source origins explicit. Establish independent
execution agreement before using it for code generation or optimization.

The first implementation is an isolated scalar experiment behind a unit-facing
API. Normal compilation continues through the typed AST. The full milestone also
requires plain records, fixed arrays, existing access modes,
PID behavior, emitted native code and eventually emitted EnforceScript. The
record/PID evaluator phase below closes only its explicitly tested portion.

Admission to each extension requires an immutable compiler/source baseline,
passing applicable Stage A semantic regressions and dependable Stage B evidence.
Engine execution remains a separate gate. A native test cannot establish engine
behavior, and source-map association cannot establish runtime correctness.

No optimization family becomes released because this IR exists. No whole-program
purity, complete alias analysis, owning-container lifecycle or engine-object
retention contract is supplied by this packet.

## D0: scalar bootstrap admission

The compiler agent's initial design uses arena-owned indexed tables for functions,
places, values, instructions, argument lists and nested regions. The model and
its evaluator must not retain executable AST nodes or dispatch back into AST
evaluation. AST references are permitted during lowering only.

| Area | Initial admitted behavior | Explicitly deferred |
|---|---|---|
| Types | `void`, `bool`, signed 32-bit integers | f32, strings as program values, records, arrays, options, error unions, owning containers and engine references |
| Functions | Concrete free functions, scalar `let` parameters and exact return types | Receiver methods, external calls, generics, indirect calls, default parameters and other parameter modes |
| Locals | Initialized scalar locals; direct binding reads and assignments | Uninitialized paths, projections, element references, replacement of owned values |
| Expressions | Literals, admitted constants, checked scalar arithmetic, comparisons, bitwise operations and short circuit | Any operator whose failure/width contract has not received an explicit lowering and evaluator rule |
| Control | If, while, exclusive integer range-for, return, break, continue and immediate defer | Arbitrary jumps, exception handling and scope-exit user defer |
| Observations | Explicitly supported scalar print/assert operations and ordered test observations | Arbitrary I/O, timing reads, engine calls and undocumented intrinsics |

Treat this table as a maximum admission boundary, not an instruction to invent
support for every listed operation. The implemented admission check must enumerate
actual opcodes and supported intrinsics. Every omitted form fails admission with
its original span. No placeholder zero, erased instruction or fallback AST call
may stand in for an unsupported operation.

Tests can carry string names as harness metadata without admitting arbitrary
string computation. An integer shift outside the admitted count domain must keep
its existing failure classification; it is not automatically an expected
`overflow` trap. Casts and other operations need their own exact domain rule
before admission expands.

### Historical D0 implementation and evidence

This subsection records the original bool/i32 checkpoint. Its API and exclusions
are superseded by the D1 checkpoint below where explicitly stated; it is not the
current feature inventory.

The implementation is in `src/ir/ir.h`, `ir.c`, `verify.c` and `eval.c`.
Its public C unit-facing entry points are:

```c
IrProgram *ir_lower_scalar(Arena *, DiagBag *, Program *);
IrVerification ir_verify(const IrProgram *);
IrRunResult ir_test(const IrProgram *, IrRunOpts);
```

`ir_lower_scalar` requires the existing resolved, checked and ownership-checked
program. It performs an explicit admission preflight over every expression,
including unreachable expressions, before pruning unreachable instructions.
Unsupported dead strings and wrapping intrinsics therefore still fail BE1101.
The resulting arena-owned IR has no retained AST, `Type`, `Item`, or `Local`
pointers. Function identity text is copied into the IR arena. Unit comparisons
free the AST arena before invoking the IR evaluator.

The exact admitted numeric operators are checked i32 `+`, `-`, `*`, `/`, `%`,
unary plus/minus, bitwise `&`, `|`, `^`, `~`, comparisons and boolean negation,
equality, `&&` and `||`. The only intrinsics are `print`, `println` and `assert`,
with scalar i32/bool arguments. Shifts, casts, `min`, `max`, `abs`, `clamp`,
wrapping/saturating intrinsics, strings, f32 and aggregates remain unavailable.

The fixed table limits are 256 functions, 8,192 places, 16,384 values, 16,384
instructions, 4,096 regions and 32,768 argument slots. Calls admit at most 256
arguments. AST/IR nesting has a 128-level limit; combined admission/lowering work
is limited to 100,000 expression visits. These are bootstrap limits, not measured
product sizing recommendations. The existing arena allocator can still abort on
host allocation failure; this API does not claim recoverable compiler OOM.

The verifier checks table ranges, negative/unknown enum values, unique ownership,
instruction/region cycles, typed operands, structured dominance, required effects,
call/return signatures, exit context and definite initialization. It distinguishes
`INIT`, `STORE` and `LOAD`. A place has at most two static initialization sites;
two sites must belong to opposite branches of a common enclosing IF. This admits
the generated short-circuit temporary and repeated execution of one declaration
site in a loop, while rejecting a second initialization used to bypass immutable
write checks. A load needs initialization on every normal path that reaches it.
Loop steps can depend only on state known initialized before the body, because
`continue` can skip later body definitions.

`ir_test` independently evaluates these instructions without calling reference
evaluation or runtime arithmetic helpers. It verifies the IR before execution.
It records ordered test/assert/print and supported source-trap events, preserving
the first source failure and prior stdout. Default execution limits are one
million instructions, 64 MiB of cumulative frame allocations, 64 MiB of combined
output/event bytes and 128 calls. A separate combined active-region depth limit
prevents deeply nested calls and regions from multiplying stack depth unchecked.
These limits have IR-specific accounting; they do not equal AST interpreter step
or allocation counts. A requested timeout requires a supplied monotonic clock
callback; absent clock support or a requested call depth above the hard maximum
returns `IR_RUN_UNAVAILABLE` before executing instructions. Timeout, cancellation,
budget, I/O, invalid-IR, unavailable, failed-assertion and source-trap outcomes are
distinct. None is silently converted into a passing expected trap.

The final focused snapshot at
[`build/ir-unit-final-ybkc8tr1/results.json`](../../build/ir-unit-final-ybkc8tr1/results.json)
records all captured C/header hashes, the Clang hash, exact compiler arguments,
unit binary hash and raw output. It passed **331 unit cases / 2,163 checks**, of
which **18 cases** exercise this IR API. Cases compare independent AST and IR
stdout/events plus fixed expected numeric results; cover range `continue`, nested
loops, extrema-adjacent bounds, recursion, short circuit, immediate defer,
immutable loop locals, first-failure ordering and failed assertions; and reject
malformed indices, use-before-definition, branch-value leakage, effects, cycles,
call arity, enum values and initialization. A well-typed ADD-to-SUB mutant passes
structural verification and fails the semantic test, demonstrating why both
checks are required. Separate tests exercise missing timeout capability, a fake
monotonic clock, cancellation and resource budgets.

This evidence is for that immutable unit snapshot. The final integrated
foundation and sanitizer evidence belongs in the implementation-state record;
it must not be inferred from the focused unit result.

Current limitations remain explicit: the IR retains source provenance, but it
has no source-manifest/length table and `ir_verify` does not prove source-span
bounds or artifact/source freshness. There is no persisted IR format, IR dump,
IR-to-C emitter, Enforce emitter, optimizer, f32/PID coverage, owning storage or
registered array-root observation in D0. Numeric IDs use `uint32_t` fields;
role and ownership separation is enforced by the verifier, not by distinct C
integer types. `--lowering ir` remains unavailable and ordinary compilation still
uses the existing AST backend.

## D1 checkpoint: finite f32 and independently checked retained source identity

This records the D1 baseline. The D2 subsection supersedes its schema number and
record/method/mode/default exclusions; its numeric and source contracts remain.

The current experimental C entry point is:

```c
IrProgram *ir_lower(Arena *, DiagBag *, const SourceMap *, Program *);
```

It replaces the old unit-only `ir_lower_scalar` API. `ir_verify` and `ir_test`
retain their roles. The caller supplies the exact source map used to parse and
check the program. The completed IR still contains no AST/type/declaration
pointers and can execute after that arena is freed. Ordinary compilation and
all public lowering-selection behavior remain unchanged.

The D1 IR schema is version 2. It owns an ordered source table containing
copied paths, copied source bytes and SHA-256 values. Source limits are 256 files,
32 MiB of combined text and 32,768 bytes per path. Its manifest hash uses the
`beryl-ir-source-manifest-v1` domain tag followed by a little-endian u32 file
count and length-prefixed path/text byte strings in source-id order. The
manifest is an IR-specific identity format; it must not be substituted for a
different driver's fingerprint format merely because both use SHA-256.

The verifier recomputes each source hash and the ordered manifest hash from the
retained bytes. It checks every function/local declaration span, region span,
instruction origin, present expansion span and call-argument observation span
against the appropriate source length using subtraction-based bounds checks.
Missing files, overflowing spans, stale retained hashes and source-table
reordering fail verification. Generated operations retain real source origins;
the existing outermost default-expansion metadata is preserved when present.
The full nested expansion history is still absent from the AST. These checks
establish bounded provenance and retained-byte identity; they do not independently
prove the lowering was correct, authenticate the calling compiler, or establish
that the live filesystem has not changed. External evidence must bind the
retained manifest to the intended input snapshot.

Finite `f32` literals, local values, parameters, returns, arithmetic and
comparisons are now admitted. Floating constants are retained as exact binary32
bit patterns. The independent evaluator uses binary32 objects for each operation
and preserves the IR's original grouping and operation order. Tests run with
`-ffp-contract=off -fno-fast-math` and the tested host's normal floating-point
environment. This is not a universal cross-platform or alternate-rounding-mode
equivalence claim.

Current numeric additions are:

- Finite f32 add, subtract, multiply, divide and negation; numeric comparisons.
- Checked numeric casts among admitted i32/f32 destinations and i32/f32/bool
  inputs, including truncating finite f32-to-i32 conversions within range.
- `min`, `max`, `abs` and `clamp`, preserving operand evaluation order, tie choice,
  signed-zero representation and the existing behavior for reversed clamp bounds.
- i32 wrapping add/subtract/multiply, saturating add/subtract and shifts with
  explicit count checks and arithmetic right-shift bit semantics. These are
  required by the existing PID test generator, rather than newly inferred PID
  behavior.

Float print observations include exact f32 bits and their actual argument spans,
in addition to ordinary text output. Nonfinite results, out-of-range float casts
and invalid shift counts remain failures outside their admitted execution domain.
They have no fabricated typed integer-overflow/division-by-zero terminal marker.
The expected-source-trap categories are not expanded by this checkpoint.

The focused immutable source capture is
[`build/ir-f32-sjuxu_3z/results.json`](../../build/ir-f32-sjuxu_3z/results.json).
Its optimized-host rerun is
[`results-O2.json`](../../build/ir-f32-sjuxu_3z/results-O2.json).
Both passed **339 unit cases / 2,409 checks**, including **26 IR cases**. The
records contain exact compiler arguments, every captured source dependency
(including generated `.inc` files), tool and unit-binary hashes, and raw results.
The only source change after that focused capture was an `ir.h` comment update;
final integration evidence must identify its own complete source snapshot.

Validation includes independently specified grouping answers, binary32 rounding
fixtures, signed zeros, casts, wrapping/saturating boundaries, checked shift
failures, nonfinite results, exact AST/IR stdout/event comparisons and AST-arena
release before IR execution. An exact 1.0f32 observation is checked against
binary32 bits `0x3f800000`. Infinity/NaN constant mutations are rejected by the
verifier; changing 1.0 to a valid 2.0 constant passes structural verification but
fails the analytical semantic assertion. Source-text/hash/order mutations and
malformed origin/expansion spans are also rejected.

At the D1 checkpoint, plain records, fixed arrays, methods, `inout`, `set`, `sink`, uninitialized
declarations and default-parameter admission are still unavailable at this
checkpoint. `f64`, owning containers, engine references, arbitrary I/O and
`sqrt` remain outside this IR subset. The complete PID package has **not** yet
executed through this IR. There is still no IR-to-C/Enforce emitter, portable IR
serialization, optimizer or public IR lowering selection. The record/array/mode
extension must land as a separately validated phase, followed by the actual PID
corpus; no PID parity is inferred from these scalar tests.

### Representation and admitted operations

Completed IR owns topologically ordered record and field tables. Primitive type
IDs remain fixed; record IDs identify copied qualified declarations. Fields own
their declaration identity, source span, type and scalar-cell offset. The verifier
rejects duplicate record/field names, cycles or forward type references, invalid
field ranges, cell-count/offset disagreements and invalid declaration spans.
The new limits are 256 record types, 2,048 fields and 256 scalar cells per record.
Empty, generic, recursive and non-admitted field types remain unavailable.

Evaluator storage is an independent flat sequence of bool/i32/f32 cells, bounded
by the existing cumulative frame-byte budget. Each ordinary record value has its
own storage. Loads, construction, assignment, parameter values and returns copy
all cells recursively represented by the record layout. A return is copied into
the caller's result storage before the callee frame is freed. This is an initial
correctness representation, not a claim that flat cells or eager copies are fast.

Static field places record their exact parent place and declared field index.
The verifier checks parent ownership, preceding parent identity, inherited
mutability, exact field type and root initialization. No pointer to an AST node,
semantic `Type`, source string in the AST arena or engine object is retained.

The admitted extension includes:

- Initialized plain records, including nested records and independent value copies.
- Record literals in source initializer order; checker-expanded default fields.
- Field reads from locals and returned record values; static field assignments.
- Concrete associated functions and receiver methods resolved by declaration identity.
- Scalar and record `let`/`inout` parameters; defaults already expanded by semantic analysis.
- Read-only record-place arguments borrowed for the duration of a call, scalar
  `let` arguments captured as values, and `inout` arguments connected to the
  caller's initialized mutable storage.

Every place argument has an explicit `IR_CAPTURE` before subsequent argument
evaluation. Its consuming call must be later in the same region and use it once.
Overlapping mutable/read or mutable/mutable captures in one call reject.
Disjoint record fields may be passed independently as `inout` values. The capture
interval rejects overlapping writes and inout targets; an interposed call may
write only through its explicit inout arguments because global storage, escaping
references and mutable let parameters are unavailable in this IR. Branching or
control flow across an interval remains conservatively rejected.

Projected assignments also have an explicit `IR_DESTINATION`, consumed by the
corresponding same-place `IR_STORE`. It precedes the RHS and any compound
old-value load. Its interval rejects overlapping RHS writes/calls and control
flow. The verifier requires this token on every projected store; deleting,
reusing or retargeting it is invalid IR. Whole-root stores retain their stable
binding address and do not use a projected-destination token.

These constraints intentionally reject some safe programs. In particular, a
projected assignment whose RHS calls an overlapping inout function is unavailable
even if that function would only update one scalar field safely. There is no
silent fallback to AST execution, and no general lifetime or alias theorem is
claimed beyond this admitted representation.

### Reviewed reference/native discrepancy and the admission boundary

The independent review found this previously admitted source:

```beryl
struct R { x: i32 }
fn replace(inout r: R) -> i32 {
    r = R{x: 10}
    return 7
}
test "replace" {
    var r = R{x: 1}
    r.x = replace(inout r)
    println(r.x)
}
```

The preserved installed AST reference printed **10**, while its generated native
C printed **7** at both O0 and O2. Both completed successfully. The source,
generated C, runtime hashes, compiler identity and raw subprocess results are in
[`destination-repro/results.json`](../../build/ir-record-stage/destination-repro/results.json).
The reference retained a nested `Value` address that became detached when the RHS
replaced its ancestor record. Native inline storage retained the root's field
address. Agreement with either representation is not a settled language rule.

The research blueprint requires retaining a valid exclusive destination or
rejecting invalidating RHS effects. This D2 phase therefore rejects the example
with BE1101. Shared reference admission is being reconciled separately; this
packet does not silently change reference behavior or claim that the reproduced
10 is the required language answer. Future generalization needs an explicit
destination-lifetime contract and agreement across all compared backends.

## Data representation and identities

Keep the first model small enough to audit without an optimizer:

- A module owns indexed tables with checked finite limits. The verifier checks
  each index according to its role and owning function; an unchecked integer
  field is not itself evidence that a reference is valid.
- Functions own parameters, local places, entry regions and return types.
- Places identify a declaration and its storage role. D0 has direct scalar
  bindings only; later projection paths must be explicit typed objects.
- Values are typed single-definition results. Reading a mutable place creates a
  value at a particular point; that value does not change when the place changes.
- Instructions reference already defined operands, optional destinations and
  explicit nested regions. Reads, initialization, writes, checked arithmetic,
  calls, observations and exits remain distinct operations.
- Each region has an owner and ordered instruction sequence. D0 function bodies
  end through explicit returns and loop conditions yield a bool; branch and step
  regions may fall through. IF and LOOP own their child regions; a child cannot
  belong to two parents.
- Keep source provenance beside operations, including operations introduced by
  lowering. Generated operations never acquire guessed source coordinates.

Use qualified declaration identity for functions and a declaration-based local
identity for places. Deterministic serialization must exclude raw pointers,
allocator addresses and process IDs. Any numbering depends on a documented
deterministic traversal; semantic identity must not rely on accidental allocation
order or identical short names.

Source `file_id` is an index into the exact ordered source manifest of that
compilation. It is not a persistent global identity. A portable location combines
the source-manifest fingerprint, file identity and byte span. Pair generated
locations with the generated artifact hash. Record target/compiler identity
separately from the source identity.

## Exact lowering rules

Evaluate binary operands from left to right. For `&&` and `||`, lower the second
operand into a conditional region; do not compute it in the parent before the
branch. Failures and observations in a skipped operand must remain absent.

Evaluate receiver/arguments in their established order when those forms become
admitted. A D0 call lowers scalar `let` arguments to ordered value operands.
Conservative call effects remain present even when an example happens not to
write or print.

For ordinary assignment, identify/evaluate the destination before the RHS,
evaluate the RHS, then perform replacement. For compound assignment, additionally
read and preserve the old destination value before evaluating the RHS. Later
array/record projections must preserve index evaluation, bounds-check timing and
failure sites. D0 direct locals do not prove that projected assignments work.

Represent an exclusive range loop with separately evaluated lower and upper
bounds, a condition region, a body region and an explicit step region. Bounds
are evaluated once, in order. Continue transfers to the step; break skips it;
return exits the function. Do not introduce an i32 overflow at a boundary where
the existing interpreter's loop bookkeeping does not expose one. Include empty,
descending and extrema-adjacent ranges in admission tests.

Keep `defer` immediate: its expression executes at its current statement position.
It does not register cleanup. Later compiler-generated destruction and any future
versioned user scope-exit feature are separate work.

Keep integer widths and arithmetic categories explicit. Checked addition,
subtraction, multiplication, negation and division cannot inherit host C undefined
behavior. In the existing reference, `INT32_MIN / -1` traps while
`INT32_MIN % -1` returns zero. Bitwise operations use exact 32-bit patterns.
Shifts need explicit count validation and signed-right-shift semantics.

Default expansion already occurs on resolved, checked declarations. Lower the
per-occurrence expression and retain both its template span and its outermost
request span. The current AST does **not** retain the complete intermediate nested
expansion chain. Neither the IR dump nor a diagnostic should invent that chain.

## Verifier and failure contract

Proposed diagnostic slots are BE1101 for unsupported IR admission and BE1102 for
invalid IR. Reserve/check them against the diagnostic registry before use. A
failed verifier is a compiler failure; it must never select a guessed value or
execute partially verified instructions.

Verify at least:

1. Table counts, all referenced indices, finite nesting, linked-list cycles and
   instruction reachability within the intended owner.
2. One definition per value, operand/result types, place types, argument arity,
   callee identity and return consistency.
3. Function/region ownership and structured dominance: a branch-local result
   cannot leak to a sibling or parent without an explicit merge/region result.
4. Required initialization before every load and valid initialization/write
   destinations. Scalar initialization does not establish later ownership rules.
5. Valid terminators and exit targets; break/continue must belong to the correct
   active loop, and returns must match the containing function.
6. Checked arithmetic and observation effects cannot be absent from operations
   that require them. Calls conservatively include relevant failure/observation
   effects until independently justified summaries exist.
7. Every semantic operation has valid source provenance. Synthetic administrative
   operations have an explicit reason and related source, never a fabricated
   token span.

Effect masks initially describe local reads/writes, failure, observations and
control exits. They are conservative evidence for this admitted representation,
not complete interprocedural effect contracts for the public language.

Place hard limits on tables, nesting, lowering work and evaluator work/call depth.
Check multiplication/addition used for allocations. Exhaustion is a resource
outcome, not a source trap. Treat timeout, cancellation and output I/O failure
separately. Tests must ensure a failed or incomplete trace never passes an
expected-trap comparison.

## Independent execution and validation matrix

The IR evaluator may share immutable type descriptions, manifest hashing and
event serialization. It must implement its own dispatch, checked arithmetic,
storage access and control transitions. Do not call the AST evaluator or emitted
runtime arithmetic helpers to obtain an answer.

Start with analytical fixtures whose outputs are specified independently. Add
AST-reference versus IR evaluation with complete admitted observable streams:
ordered print/assert/test events, stdout, final outcome and first source-failure
site. A matching scalar return alone is insufficient.

Deliberately mutate valid IR copies to test the verifier and comparison harness:
reverse two observable operands; execute a short-circuit RHS unconditionally;
move an old-LHS load after RHS evaluation; omit a loop step; misdirect continue;
replace a checked operation; change a return type; use an undefined value; reuse a
region from another function; create an instruction cycle; omit an observation
effect; corrupt a source span. Each mutation must fail at the intended layer.

Extend in this order, with a new admission gate for each step:

| Packet | Added capability | Required evidence |
|---|---|---|
| D0 | Isolated bool/i32 model, lowering, verifier and evaluator | Analytical fixtures, AST/IR traces and malformed-IR rejection |
| D1 | Finite f32 and exact admitted intrinsics | Preserved grouping/width; no contraction or fast-math; independent numerical fixtures |
| D2 | Plain records, fixed arrays, typed projections and existing access modes | Copy/mutation/order tests, checked index timing, alias-sensitive calls and root-state comparisons |
| D3 | Unoptimized IR-to-C | AST reference / IR interpreter / AST-to-C O0/O2 / IR-to-C O0/O2 comparison on exact artifact identities |
| D4 | Full current PID through that matrix | Complete operation sequences, persistent state, established numerical tolerances and mutation detection |
| D5 | EnforceScript lowering for the same admitted subset | Script compilation, engine pure-function comparisons, source association and isolated integration |

The currently supported optional watched root in expected-trap differential tests
is one initialized top-level test-local i32 array, bounded to 4,096 elements. That
facility is useful for later D2 validation. It does not make arrays part of D0,
establish arbitrary heap-state equivalence, or cover all mutation aliases.

## Files, compatibility and rollout

The experimental implementation is in `src/ir/ir.h`, `src/ir/ir.c`,
`src/ir/verify.c` and `src/ir/eval.c`, with fixtures in `tests/unit/test_ir.c`.
Keep extensions under these independently reviewable boundaries. Do not route production
emitters or public CLI selection to the experiment while the applicable gates
remain incomplete.

Existing `.be` syntax and access modes remain unchanged. Existing native and
Enfusion output remain on their verified paths. Existing test backend selection
stays explicit. `--opt off` still controls Beryl optimization policy rather than
silently changing the selected Clang optimization level.

Opt-in Enfusion sidecars currently provide line-to-span association only. Helper
origins identify the declaration/use that caused generation; shared helper code
is not attributed to every possible consumer. Engine columns remain raw, with
interpolation marked unavailable. Exact cross-file nested-default tests validate
template and outermost request locations; full expansion chains are deferred.

Metadata collection is optional in the compiler. Sidecar size and record counts
can be measured separately from generated code size; byte-identical output proves
that source-map collection did not rewrite runtime code. It does not prove zero
compiler overhead. The diagnostic mapper indexes line starts once and validates
spans against exact source bytes instead of repeatedly scanning generated
prefixes. Retained sidecars/source manifests remain subject to explicit storage
budgets in later whole-project tooling.

## Completion evidence and stop rules

For each packet retain compiler and source hashes, accepted/rejected feature
inventory, exact commands, raw traces, outcome classifications and mutation-test
results. Record unsupported targets explicitly. Do not label a timeout, missing
engine run or partial corpus as a pass.

A D0 success authorizes further experimental work; it does not close Stage D.
Stop migration on any semantic mismatch, uncontrolled resource growth, unverified
ownership crossing or source identity ambiguity. Keep the existing AST path as
the release path until the relevant complete matrix passes. No optimizer,
incremental cache or speculative execution plan is enabled by this packet.
